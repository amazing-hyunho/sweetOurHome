# 집 PC 자동 매물 수집

2026-10-18: 별도로 만든 **[파이썬 브라우저 연결 방식](python-collector.md)**에서 개별 매물 12개를 실제 Firebase에 저장했습니다. 아래는 이전 Node 독립 브라우저 방식의 실행법과 실패 진단 기록입니다.

웹의 관심 단지에 정확한 단지명과 네이버 단지 링크를 저장하고 **집 PC에서 이 링크의 매매 수집**을 켭니다. Firebase 목록을 읽는 PC가 Edge 브라우저로 페이지를 열고, 개별 매매 카드의 가격·전용면적·층·원문 링크·관찰 시각을 Firebase에 저장합니다. 웹은 기존 실시간 구독으로 변경을 표시합니다.

## 실행

Windows, Node.js 24 이상, Microsoft Edge가 필요합니다.

```powershell
npm ci
npm run collect
# 계속 실행: 수집 종료 후 10분 대기, 다음 회차에 링크 목록을 다시 읽음
npm run collect -- --watch
```

`collect.cmd`를 더블클릭해도 계속 실행합니다. Ctrl+C로 종료합니다. PC 종료·절전 중에는 수집이 멈추며 웹은 마지막 결과를 보여줍니다. 로그인 시 자동 실행하려면 `collect.cmd`의 바로가기를 Windows 시작프로그램 폴더(`shell:startup`)에 추가하세요. `--headed`는 브라우저를 표시하는 진단 옵션입니다. 기본값은 백그라운드 Edge이고 `SWEET_HOME_BROWSER=chrome`으로 Chrome을 선택할 수 있습니다.

기존에 등록된 단지는 편집에서 수집 체크를 켜야 할 수 있습니다. 관심 지역만 등록하면 수집하지 않습니다. PC가 실행 중인지 웹에서 단정하지 않으며, 단지별 최근 시도·최근 매물 확인·오류를 표시합니다.

브라우저 쿠키와 사이트 저장소는 `%LOCALAPPDATA%\sweetOurHome\collector\browser-profile`에 유지합니다. 사용자의 평소 Edge 프로필과는 별개이며 기존 브라우저의 쿠키를 복사하지 않습니다. 같은 전용 프로필을 다음 실행에서도 재사용합니다.

HTTP 429가 감지되면 해당 회차의 나머지 단지 조회를 중단합니다. 기본 30분과 `Retry-After` 중 더 긴 시간을 기다리며 대기 시각은 같은 PC의 `cooldown.json`에 저장해 재시작해도 지킵니다. 정상 수집 간격은 기존처럼 10분입니다.

## 저장과 범위

- 부분 수집입니다. 현재 렌더링된 개별 매매 링크만 수집하며 묶음 광고와 전체 목록 완전성은 보장하지 않습니다. 빈 화면은 매물 0건으로 확정하지 않습니다.
- 읽지 못한 매물은 삭제하지 않습니다. 각 매물의 관찰 시각을 확인하세요. 사라진 광고의 종료 판정은 아직 하지 않습니다.
- 사용자 메모·찜·목표 가격을 보존합니다. 수집 후 최신 Firebase 문서를 다시 읽고 버전 조건으로 저장하며, 충돌하면 최대 3회 최신 상태에 다시 병합합니다. 삭제되거나 링크가 바뀐 단지에는 이전 결과를 쓰지 않습니다.
- 잘못된 링크, 네이버 오류 화면, 로딩 실패, 파싱 오류는 단지 오류로 저장하고 마지막 성공 결과를 유지합니다. 실패한 단지를 즉시 반복 요청하지 않습니다.
- 현재는 기존 `households/home` 문서를 사용합니다. 700KB 및 5,000개 매물 한도를 넘으면 저장하지 않고 PC 로그에 오류를 남깁니다. 대규모 목록은 별도 컬렉션으로 이전해야 합니다.
- PC별 잠금 파일로 중복 실행을 막습니다. 서로 다른 PC의 동시 실행은 막지 않으므로 한 PC에서 실행하세요.

## 현재 검증 상태 (2026-10-15)

사용자가 제공한 https://naver.me/xEXYkQ4W 는 정상 링크입니다. 앱 내 브라우저에서 성복역현대홈타운(네이버 단지 ID 8692), 462세대, 매매 목록 15개(개별 링크 11개, 묶음 4개)를 확인했습니다. Firebase에 해당 단지와 링크를 등록하고 PC 수집을 켰습니다.

PC의 독립 실행 브라우저에서는 같은 링크가 네이버 오류 화면으로 이동했습니다. 단축 링크뿐 아니라 화면에서 확인한 매매 목록 직접 링크로도 재현됐습니다. 이는 링크 자체가 잘못됐다는 증거가 아닙니다. 실제 자동 매물 저장은 아직 성공하지 않았으며 Firebase에는 실패 상태와 확인 시각이 저장되어 있습니다. PC 수집기는 상시 실행하지 않았습니다.

추가 진단에서 문서 HTML은 HTTP 200이었으나 페이지가 요청한 `/front-api/v1/complex` 응답은 HTTP 429였고, 이후 `/404`로 이동한 것을 확인했습니다. 수집기는 브라우저 응답을 관찰해 이 경우를 단지 정보 조회 제한으로 표시합니다. 별도 내부 API를 직접 호출하거나 제한을 우회하지 않습니다. 이 실행 환경의 현재 조회 실패이며 전체 구조의 불가능 판정은 아닙니다.

실제 DOM을 확인해 가격이 없는 ‘매물 보러가기’ 링크의 주변 카드를 읽도록 수정했습니다. 최근 조회 링크와 묶음 광고가 섞이지 않는 브라우저 회귀 검증은 `npm run test:collector:browser`로 실행합니다. 테스트는 로컬 HTML을 사용하며 실제 네이버 수집 성공을 의미하지 않습니다.

## 전용 프로필 시험 (2026-10-16)

`launchPersistentContext`와 `--headed`로 전용 프로필을 생성해 한 차례 실행했습니다. 단지 페이지는 다시 네이버 오류 화면으로 이동했고 Firebase에 실패 상태가 저장됐습니다. 이 회차에서는 수집기가 429 응답을 포착하지 못했으므로 이전 진단과 동일한 원인이라고 확정하지 않습니다. 프로필 유지 방식으로 해결됐다는 증거는 없으며 실제 자동 매물 저장은 여전히 미완료입니다.

일반 Edge 브라우저 비교도 시도했지만 현재 연결된 브라우저 도구에는 Edge가 없고 앱 내 브라우저만 있습니다. 따라서 평소 사용하는 Edge에서의 접속 결과는 별도로 확인해야 합니다. 테스트 41개와 로컬 HTML을 이용한 Edge DOM 회귀 검증은 통과했습니다. 상시 수집기는 실행하지 않았습니다.

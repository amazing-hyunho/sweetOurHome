# PC 관찰 엔진

현재 입력원은 Firebase 공동 목록이다. 네이버에 신규 등록된 매물을 자동으로 찾는 수집기는 아직 아니다.
웹에서 직접 등록하거나 가격을 수정한 매물의 변화를 기록한다. 자동 수집 경로 확보 후 연결할 기반이다.

## 실행

Node 24에서 저장소 폴더의 터미널로 실행한다.

```
npm run observe
npm run observe -- --status
npm run observe -- --history
npm run observe -- --events
```

기본 명령은 한 번 읽고 종료한다. --history는 최근 가격 변경 50건, --events는 최근 알림 50건과 전송 상태를 보여준다.

계속 관찰하려면 저장소의 observe.cmd를 실행하거나 아래 명령을 사용한다.

```
npm run observe -- --watch
```

5분마다 Firebase 공동 목록을 확인하며 Ctrl+C로 종료한다. PC 시작 프로그램은 등록하지 않는다.
웹앱에서 직접 수정한 값만 확인하므로 네이버 변경 후 10분 이내 발견을 달성한 것은 아니다.
첫 실행은 기준선만 저장하고 기존 매물 알림은 만들지 않는다.
이후 실행은 신규 급매 후보, 후보로 전환된 매물, 후보의 추가 인하, 조건에 맞는 찜 매물 가격 인하를 감지한다.
같은 관찰 결과를 반복하거나 PC를 재시작해도 중복 이벤트를 만들지 않는다.
목록에서 삭제된 항목은 거래 완료가 아닌 목록 삭제로 기록하고 이력을 보존한다.
조회 실패 시 기존 기록과 마지막 성공 시각을 유지한다.

SQLite 파일은 %LOCALAPPDATA%\sweetOurHome\observer\history.sqlite 에 보관된다. GitHub/OneDrive에 올리지 않는다.
테스트는 SWEET_HOME_OBSERVER_DIR로 별도 폴더를 지정할 수 있다.

## Telegram 준비 후

위 observer 폴더 안에 telegram.json을 만들고 아래 형식으로 입력한다. 토큰은 웹앱/공개 저장소에 넣지 않는다.

```json
{"token":"봇 토큰", "chatId":"-그룹 숫자 ID"}
```

```
npm run observe -- --send
npm run observe -- --watch --send
```

명시적인 --send 옵션일 때만 실제 메시지를 보낸다. 한 번에 최대 10개.
대기 중인 동일 매물의 과거 가격 이벤트는 최신 이벤트로 대체한다.
찜 해제/층수 수정/목표 가격 변경으로 조건에서 벗어난 대기 알림은 취소한다.
메모는 전송하지 않는다. 공개 목록의 입력값 기준이라는 설명과 매물 링크를 보낸다.
네트워크 실패로 전달 여부가 불분명한 경우 uncertain, 전송 도중 종료되면 sending 상태로 남긴다.
중복 방지를 위해 이 상태는 자동 재전송하지 않으며 실제 그룹방 확인 후 수동 복구가 필요하다.

## 아직 미구현

네이버 자동 수집, 실거래 API 연동, 10분 내 발견 목표, PC 자동 시작, 웹의 PC 상태/가격 이력 표시.
Telegram 실전송은 봇과 그룹 설정 후 별도 검증해야 한다.

# 스냅샷 병합과 Firebase 반영

이 명령은 사용자가 제공한 JSON 스냅샷을 가져온다. 네이버 접속, 브라우저 실행, 반복 수집은 수행하지 않는다.
반복 수집을 허용하는 데이터 경로는 아직 확보하지 못했다. 기존 네이버 내부 API 요청의 429와 페이지 이용 제한을 브라우저 자동화로 우회하지 않는다.

## 입력 형식

```json
{
  "observedAt": "2026-10-15T03:00:00Z",
  "expectedCount": 1,
  "rows": [
    {
      "text": "테스트아파트 201동\n매매 12억\n아파트108㎡ (전용84.85)17/20층동향",
      "url": "/articles/123"
    }
  ]
}
```

observedAt은 파일 생성 시각이 아닌 실제 관찰 시각이다. expectedCount는 로딩 완료 후 화면에 표시된 카드 개수이다.
저/중/고 표기는 정확한 층수를 추정하지 않고 null로 유지한다. 개별 매물 ID가 없는 묶음 카드는 건너뛴다.
예시 데이터는 형식 설명용이며 실제 매물이 아니다.

## 기본값: 미리보기

### 웹에서 사용

1. 관찰 대시보드의 **스냅샷 가져오기** 또는 관찰 설정의 **매물 스냅샷 가져오기**를 누른다.
2. 반영할 단지를 선택하고 위 형식의 JSON 파일을 선택한다. JSON 직접 붙여넣기도 가능하다.
3. **변경 미리보기**에서 추가/갱신/묶음 제외 개수, 가격과 층수를 확인한다.
4. **확인한 변경 반영**을 눌렀을 때만 공동 목록에 저장한다.

이 기능은 네이버 링크를 조회하거나 파일을 자동 생성하지 않는다. 미리보기 뒤 공동 목록이나 입력이 바뀌면 다시 미리보기해야 한다.
이 브라우저의 마지막 가져오기 직전 상태는 자동으로 로컬 백업되며, 관찰 설정의 **가져오기 전 백업 다운로드**로 받을 수 있다. 백업은 기기 간 공유되지 않고 다음 가져오기 시 교체된다.
카드에는 스냅샷 가져오기 출처와 관찰 날짜를 표시한다.

### PC 명령으로 사용

웹에서 먼저 관심 단지를 등록한다. --complex는 등록된 단지의 내부 ID이며 단지명으로 추정하지 않는다.

```
npm run import:snapshot -- --file 스냅샷.json --complex 등록한단지ID
```

Firebase 공동 목록을 읽어 추가/갱신/건너뛸 개수를 출력하지만 저장하지 않는다.
웹에 등록한 단지명과 스냅샷의 단지명이 정확히 일치해야 한다.
공동 목록을 사용하지 않는 오프라인 검증은 --state 백업.json 옵션으로 실행한다. --state와 --write는 함께 사용할 수 없다.

## 명시적인 반영

사용 권한이 있는 스냅샷에 대해서만 다음 옵션으로 반영한다.

```
npm run import:snapshot -- --file 스냅샷.json --complex 등록한단지ID --write
```

- 원문 매물 URL이 일치하면 기존 수동 등록 기록의 ID를 재사용한다.
- 가격/전용면적/정확한 층/원문 URL/관찰 일시만 갱신한다.
- 기존 사용자 설명, 찜, 메모, 비교 실거래, 단지 목표 가격은 보존한다. 새로 발견한 항목은 자동 찜하지 않는다.
- 스냅샷에 없는 기존 매물은 삭제하거나 거래 완료로 표시하지 않는다.
- 오래된 관찰 일시는 거부한다. 단, 예전 수동 기록에 정확한 시각이 없으면 확인 날짜까지만 비교할 수 있다.
- 저장 직전 읽은 문서의 updateTime과 revision을 기준으로 저장한다. 다른 기기 변경과 충돌하면 덮어쓰지 않고 중단한다.
- Firebase의 서버 시각으로 updatedAt을 기록하며 기존 firestore.rules와 함께 동작하도록 구성했다.
- 반영 전 상태는 %LOCALAPPDATA%\sweetOurHome\imports 폴더에 JSON으로 백업한다.
- 기존 단일 공동 목록 문서의 JSON 700KB 제한을 유지한다. 대규모 자동 수집용 컬렉션 구조는 별도 설계가 필요하다.

가져온 항목에는 source=naver-snapshot, sourceObservedAt을 보존한다. 기존 출처 정보가 없는 수동 항목은 source=manual로 정규화된다.

## 검증 상태

성복역현대홈타운의 기존 로컬 추출 파일로 오프라인 미리보기를 실행했다. 카드 15개 중 개별 ID 11개 추가 예정, 묶음 4개 건너뛰기, 삭제 0건을 확인했다. 이 파일은 Firebase에 반영하지 않았다.
병합 보존/중복/오래된 시각/문서 동시 수정 충돌/REST 값 인코딩 테스트를 통과했다. Firebase 실서비스 쓰기는 아직 검증하지 않았으며 테스트에서는 요청 본문과 조건부 저장 응답을 모의 검증했다.

웹 UI는 Firebase에서 분리한 로컬 테스트 데이터로 미리보기 → 반영 → 새로고침 후 유지, 메모 내용과 찜 보존, 잘못된 JSON 입력 시 반영 차단을 확인했다. 이 테스트로 실제 공동 목록은 변경하지 않았다.

## 자동 수집을 위한 남은 조건

네이버 공식 오픈 API 목록에서 매물 조회 API를 확인하지 못했다.
https://developers.naver.com/products/intro/plan/plan.md

공식 제휴 또는 반복 수집이 허용된 데이터 제공 경로를 먼저 확보해야 한다. 수집기의 인증/사용 조건/필드 제공 범위가 확인된 뒤 이 병합 코드에 연결한다. 현재 observe --watch는 Firebase 입력값 확인만 수행하며 네이버 반복 수집을 활성화하지 않는다.
